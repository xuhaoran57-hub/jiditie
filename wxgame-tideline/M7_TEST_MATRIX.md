# M7 真机与回归测试矩阵

文档版本：0.1 · 记录状态：2026-09-01

本文件把自动化回归和微信开发者工具/真机验收分开记录。自动化测试已经在
Node 环境运行；真机栏位必须由测试人员填入设备、基础库版本、截图或录屏路径，
不能用 mock 结果替代。

## 1. 通过标准

- 三个关卡都能走完“路线页 → 游戏 → 成功/失败结算 → 重试/下一站/返回路线”。
- iOS 与 Android 各至少覆盖一台低端机和一台主流机；竖屏安全区、触摸和音频均通过。
- 切后台 10 秒再回来，倒计时不把后台时间计入；重复启动不会产生第二条 ticker。
- 在目标低端机上，220 人压力场景的可见帧率不低于 30 FPS，且没有输入卡死。
- 静音、无网络、损坏存档、低电量提示等异常场景可以继续离线完成一局。

## 4. 手工场景脚本

### Q-02 触摸、布局和音频

1. 冷启动后点击首张路线卡；确认只进入一次游戏页。
2. 单指按住摇杆向四个方向移动，再滑出摇杆、抬起和取消；确认角色停止且没有残留触点。
3. 两指同时操作摇杆和疏导按钮；确认按钮脉冲只触发一次，松手后可再次触发。
4. 点选不同车门；确认推荐门、阻塞门和命中区域与画面一致。
5. 首次有效触摸后确认氛围音尝试播放；系统静音或游戏静音后确认不再出声；返回前台不重复叠加音频。
6. 在 375×667、414×896 和带刘海设备上确认暂停、疏导、重试、下一站按钮不被安全区遮挡。

### Q-06 生命周期与快速操作

1. 连续快速点击开始、重试、下一站、返回路线各 5 次；确认只有一个页面状态和一条 ticker。
2. 游戏中切后台 10 秒再回来；记录切换前后的 `elapsed`，差值只能来自回前台后的运行时间。
3. 游戏暂停时切后台/回前台；确认仍保持暂停，手动恢复后才继续。
4. 结算瞬间切后台、重试或返回路线；确认不会重复写入通关次数或重复播放结算音效。

### Q-07 异常、离线和低电量

1. 关闭网络/开启飞行模式，冷启动、选关、通关和失败各一次；确认没有请求失败弹窗。
2. 用开发者工具写入非法 JSON、未知版本和缺字段存档；重启后确认安全回退且首关可玩。
3. 系统静音、拒绝音频能力或删除音频 API mock；确认规则和画面仍可推进。
4. 低电量/省电模式下完成一局；记录是否出现明显降帧、触摸延迟或音频中断，并保留设备提示截图。
5. 强制杀掉小游戏后重新进入；确认本地进度、设置和解锁状态符合预期。

## 5. 缺陷分级与签字

| 级别 | 判定 | M7 要求 |
|---|---|---|
| P0 | 崩溃、无法启动、存档覆盖、触摸永久卡死 | 未修复不得进入 M8 |
| P1 | 关键关卡无法完成、倒计时跳变、真机持续低于 30 FPS | 未修复不得发布；需回归证据 |
| P2 | 局部布局、音量或文案问题，有可用绕行 | 可带修复计划，不得影响审核截图 |
| P3 | 视觉微调或非阻断建议 | 记录到 backlog |
