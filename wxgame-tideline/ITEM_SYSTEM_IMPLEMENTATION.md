# 通勤道具系统

实现日期：2026-09-13。

## 已实现流程

- **通勤喇叭**：前方最多 4 人，范围为普通疏导的 1.25 倍，侧移为 1.5 倍，效果 0.5 秒；不消耗体力或改变普通疏导冷却。无目标不扣库存，礼让和疏导次数仍计入结算。
- **延时车票**：上车／警告阶段增加 3 秒，超过警告阈值时恢复普通倒计时表现。不会重新打开事件封闭的车门，也不能在结算后复活。
- **通勤背包**：库存保存在本地。战役每局每种最多使用一次；无尽模式每场每种最多一次，下一轮不重置。
- **首次赠送**：确认本地存档不存在时，两种道具各赠 1 件。有效旧存档升级不默认补发；读取异常不当成首次进入。
- **自选领取**：先选道具，再看完整激励视频或分享好友；每次获得 1 件，先入背包，由玩家自己使用。
- **分享参与奖励**：已选择“分享返回即可领”，取消发送后返回也可以领取。没有前后台回调时可在原补给弹窗手动领取，同一次请求只发一次。
- **界面**：首页背包、关前和通关结算补给入口、局内两个快捷按钮、首礼／背包／补给弹窗，以及使用反馈。
- **失败补给**：失败结算按“重试 → 路线 → 分享图标＋车票 ×1 → 视频图标＋喇叭 ×1”排列，窄屏分两行。图标使用 Canvas 矢量绘制。两个领取按钮直接发起对应操作，每次获得指定道具 1 件；领取后先入背包，返回仍是失败结算，由玩家重试后手动使用。失败页不再显示右上角通用补给入口。
- **暂停**：局内空道具显示“道具名 +”，点击后立即暂停并打开获取页，包括上车前和本局已经用完的情况。打开当帧、领取和广告／分享期间均冻结倒计时及乘客移动，面板显示“已暂停”，关闭后继续且不补算离开时间。补充库存不重置本局使用次数；原本手动暂停不会被覆盖。
- **记录**：保留通关与综合最佳成绩，另存无道具最佳成绩。无尽整场使用标记跨轮次保留。

背包采用覆盖当前页面的面板，关闭后保留原页面及位置；规则层没有引入微信或 Canvas 依赖。

## 广告配置

当前已在 `src/runtime/reward-config.ts` 的 `REWARD_CONFIG.adUnitId` 配置激励视频广告位 `adunit-6742b53b8b86e27a`。更换广告位后执行：

```text
npm run build:wxgame
```

也可以在嵌入运行时的调用处传入 `rewardedAdUnitId` 覆盖默认配置。

若将广告位配置留空，视频补给显示暂未开放，分享、新手赠送、背包和道具使用均可工作。测试中的 `adunit-test` 只存在于测试目录，不进入正式构建。

完整观看要求 `onClose` 返回 `isEnded === true`，因此不兼容依赖缺失结果字段判成功的旧基础库行为。正式发布应选择支持该字段的基础库并完成真机联调。加载、展示成功和普通切前台不发视频奖励。

## 存档与恢复

- 数据版本升级至 v4，继续使用 `tideline.save.v1` 存储键，保留旧进度、设置和外观。
- 库存和已处理奖励标识同一次写入。广告已完成但保存失败时，可重试保存，不必重新观看。
- 启动读取异常后，打开背包／补给、保存进度或回到前台会重读存档；恢复原库存、设置及奖励记录，并合并本次会话的临时成绩和统计。未来版本仍保持保护，确认存档不存在后才补发首礼。领取前先确认可以保存，失败时提示重试，不调起广告或分享。
- 使用前先持久化扣减及待完成标识，存储失败则不使用；下次启动可补偿上次未完成的使用。
- 新手赠送按设备本地存档判断，清除数据、换机和重装不具备账号级去重。
- 这是本地库存，不能防止客户端篡改。广告完成后、任何记录尚未落盘时进程被系统终止，无法保证恢复该笔奖励。
- 分享按参与行为发奖，不验证好友收到或实际发送成功，也不设离开时长、随机失败和换群要求。
