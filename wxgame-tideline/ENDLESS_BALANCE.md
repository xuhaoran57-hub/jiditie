# 无尽模式难度校准

无尽模式采用独立客流曲线，只沿用战役车厢配色。第 13 轮继续双门和既有客流压力，
不会重新套用第一站的人数、倒计时或单门布局。战役关卡与存档格式保持兼容。

## 调整

- 第 5、6 轮分别由 83、96 人降到 60、64 人；单门宽度由 60 增至 75.2、74。
- 第 7～20 轮保持双门，人数从 100 逐步增加到 133，门宽从 74 缓慢收窄到 67.5。
- 每轮上车倒计时统一为 12 秒。NPC 基础速度平缓上升，快步事件最高 1.2 倍，
  避免模板速度和无尽倍率反复相乘。
- 车厢容量覆盖本轮候车人数，避免满员后的 NPC 永久停在门前；玩家通关仍需穿过门洞。
- 第 5 轮开始出现温和快步客流，第 14 轮开始出现带 4 秒预警的提前关门，
  关门时刻逐轮提前。两类事件错开，避免后一个事件被前一个吞掉。
- 第 20 轮后增长降速，人数最多 180，NPC 基础速度最多 48，双门宽度至少 58。

## 验证方式

正式运行时默认种子为 1。测试使用正常 `nextLevel()` 从第 1 轮连续走到第 20 轮，
检查通关结果、最高轮次和无道具纪录。在 667×375 与 844×390 两种横屏中，
每轮均有固定简单策略能无道具进入车厢且至少剩余一秒。

固定策略为直冲可用门、疏导并按预警改道、对齐门口后疏导、选择另一扇门后疏导。
摇杆每 0.1 秒调整一次，疏导约 1.05 秒尝试一次；使用正式横屏输入换算和 1/60 秒步长。
策略只读取当前可见状态，不搜索微小时机、不读取未来事件、不提高角色速度。

多种子抽样使用每个视口 20 个基础种子（1～20），轮次种子计算与正式运行时一致。
比较策略为直冲和疏导改道；第 5～20 轮、两个视口共 1,280 局。统计反映脚本表现，
不等同于真人通过率。候选路线的成功也不代表玩家第一次选择就能通关。

## 复现

```powershell
npm run test:core
npm run evaluate:endless -- --seeds=20 --from=5 --to=20 --strategies=rush,guide --output=tmp/endless-evaluation.json
```

`evaluate:endless` 默认检查 1～20 轮、30 个基础种子、两个视口和四个固定策略。
可用 `--viewports=667x375` 缩小范围。结果逐轮打印，可通过 `--output` 保存 JSON；
评估脚本和报告不进入微信发布包。

Android 触屏体验与不同机型仍需实际复测。本地模拟不包含手指遮挡、触摸延迟和误操作。
