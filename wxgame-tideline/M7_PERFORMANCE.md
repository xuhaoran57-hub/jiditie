# M7 性能与包体基线

文档版本：0.1 · 记录状态：2026-09-01

## 1. 指标和口径

MVP 首发横屏，运行时默认固定步长为 60 Hz，独立模拟基准按 30 Hz 推进；竖屏仅作为兼容性回归。低端设备的验收帧预算为 33.3 ms/帧（至少
30 FPS）；主流设备目标为 60 FPS。逻辑更新、碰撞、人群排序和 Canvas 绘制应
分别观察，不能只用平均帧率掩盖长尾卡顿。

| 指标 | M7 基线 | 说明 |
|---|---:|---|
| 目标压力人数 | 220 | 与星环城高密度关一致 |
| 单次逻辑更新 P95 | ≤ 33.3 ms（自动化严格门槛） | Node 基准用于回归趋势，不替代真机结果 |
| 真机整帧 P95 | ≤ 33.3 ms | 低端机必须满足；长帧需记录原因 |
| 真机整帧最大值 | 结算/切关短峰值可单独说明 | 连续长帧视为 P1 风险 |
| JS 堆增长 | 10 分钟稳定运行无持续线性增长 | 通过开发者工具性能面板观察 |
| 发布内容包体 | ≤ 4 MB（项目内部预算） | 以 `game.js`、`dist/`、`assets/` 合计计算 |
| `dist/` 编译产物 | ≤ 1 MB（项目内部预算） | 超出需说明依赖或拆包方案 |

## 2. 可重复基准

在项目目录执行：

```text
npm run bench:simulation
node --experimental-strip-types scripts/benchmark-simulation.mjs --strict
```

脚本默认使用 220 人、180 帧、30 帧预热，输出平均值、P50、P95、最大值、估算
FPS 和堆变化。可用参数做趋势对比：

```text
node --experimental-strip-types scripts/benchmark-simulation.mjs --actors=60 --frames=600
node --experimental-strip-types scripts/benchmark-simulation.mjs --actors=220 --frames=600 --warmup=60 --budget=33.3 --strict
```

2026-09-01 的一次 Node 基线（运行环境：Node 25，非目标手机）如下，仅作为回归
参考：

```text
actors: 220
p95Ms: 2.143
maxMs: 3.101
estimatedFpsAtP95: 466.6
```

如果硬件、Node 版本或帧数改变，应把完整 JSON 输出保存到性能记录，而不是只摘录
一个数字。`--strict` 只判断逻辑更新 P95，不宣称真机已经达标。

## 4. 当前实现与优化边界

- 规则层使用空间哈希和固定步长；M7 重点观察 200+ 角色下的邻域查询和碰撞分离。
- Canvas 采用单一绘制入口，角色图集预加载后复用，缺失或解码失败时回退几何绘制；
  避免每帧图片解码和网络加载。
- 运行时只维护一条 scheduler/ticker；快速启停和切关由 M7 测试锁定。
- 若低端机不达标，优先按顺序处理：降低远处角色更新频率、减少重复路径绘制、
  复用临时对象、降低特效粒度；不得改变安全区、容量和结算规则来“优化”指标。

## 5. 性能退出条件

- 自动化 `--strict` 基准通过，且记录提交版本和运行环境。
- D-03（低端 Android）星环城整帧 P95 ≤ 33.3 ms，无连续 5 帧以上长帧。
- 10 分钟运行和 5 次切后台/重试后无持续内存增长或 ticker 倍增。
- 发布审计显示包体、音频和 SVG 均未超过内部预算。

## 6. 微信运行性能第一批优化（2026-09-16）

基于 `bdab878` 工作区及启动优化继续修改，尚未提交；本批保留既有固定步长、碰撞迭代次数和游戏规则。

- 调度优先使用小游戏全局 `requestAnimationFrame/cancelAnimationFrame`，其次兼容注入的 `wx` 调度器，最后才回退定时器。后台取消帧回调，前台重建时间基线；过期回调不能启动第二条循环。
- 首页、路线、介绍、设置、成就、外观、结算、暂停和补给界面只在内容变化时绘制。前台保留轻量帧循环消费触摸命令；图片解码、奖励回调、提示到期和返回前台均会更新画面。运行中的触摸布局在无变化时复用。
- 将天空、车厢和站台底图缓存到一张离屏 Canvas。车门、占用条、事件、角色和 HUD 仍实时绘制。尺寸、DPR、安全区、主题和场景几何变化时复用画布重建；不支持离屏绘制时直接回退。`destroy()` 释放底图像素缓冲。
- 碰撞结果按构建时的角色对应顺序回写，避免每个乘客再次 `actors.find()`；回写查找从平方级降为线性，不改变碰撞计算顺序。

一张 667 × 375、DPR 2 的底图约占 3.82 MiB 像素内存；更大视口按实际物理像素计算，切关不叠加底图缓存。小数 DPR 按物理像素对齐回贴，避免缩放模糊和边缘透明像素重复叠加。

### 本地验证记录

环境为 Windows、Node v24.13.0。220 人、90 帧预热、360 帧采样各连续运行 3 次：

```text
node --experimental-strip-types scripts/benchmark-simulation.mjs --actors=220 --frames=360 --warmup=90
```

| 指标（ms） | 修改前 3 次 | 修改后 3 次 | 中位数变化 |
|---|---|---|---|
| 平均逻辑耗时 | 1.170 / 1.174 / 1.163 | 1.049 / 1.024 / 1.020 | 1.170 → 1.024，下降约 12.5% |
| P95 逻辑耗时 | 1.744 / 1.797 / 1.729 | 1.659 / 1.599 / 1.601 | 1.744 → 1.601，下降约 8.2% |
| 最大逻辑耗时 | 4.151 / 4.095 / 3.898 | 3.522 / 3.624 / 3.373 | 4.095 → 3.522 |

- 首页等静态页面连续空闲 120 帧，新增绘制和触摸布局构建均为 0。
- 12 个战役关卡及无尽第 6、15 轮，以 `performance-parity` 种子各推进 720 帧；每帧完整状态累计 SHA-256 与修改前一致，共 10,080 帧。覆盖 waiting、alighting、boarding、inside、exited 角色。
- Chrome Headless 的真实 Canvas 像素对比：12 关 × 3 组横竖屏/DPR/安全区 × 2 个连续场景，共 72 个画面，与原版站台绘制结果逐像素一致。包含 DPR 1、1.5、2 及缓存命中后的动态画面。
- 自动化回归包括缓存失效/降级、全局原生帧调度、后台零绘制和恢复不补算后台时间。
- `npm run check`、新增小数 DPR 回归和 `npm run check:release:strict` 全部通过，累计 143 项测试。发布审计仅保留原有 `license-pending` 非阻断提示。

以上逻辑基准、Mock 计数和桌面像素结果不代表手机 CPU 均值或 FPS 均值。用同一设备、微信版本、基础库、关卡人数和测试时长复测，重点记录首页静置、密集人流、事件场景及 5 次前后台切换后的 CPU/FPS、长帧与内存。
