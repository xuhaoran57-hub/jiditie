# M7 性能与包体基线

文档版本：0.1 · 记录状态：2026-09-01

## 1. 指标和口径

MVP 首发竖屏，固定步长为 30 Hz。低端设备的验收帧预算为 33.3 ms/帧（至少
30 FPS）；主流设备目标为 60 FPS。逻辑更新、碰撞、人群排序和 Canvas 绘制应
分别观察，不能只用平均帧率掩盖长尾卡顿。

| 指标 | M7 基线 | 说明 |
|---|---:|---|
| 目标压力人数 | 220 | 与星环城高密度关一致 |
| 单次逻辑更新 P95 | ≤ 33.3 ms（自动化严格门槛） | Node 基准用于回归趋势，不替代真机结果 |
| 真机整帧 P95 | ≤ 33.3 ms | 低端机必须满足；长帧需记录原因 |
| 真机整帧最大值 | 结算/切关短峰值可单独说明 | 连续长帧视为 P1 风险 |
| JS 堆增长 | 10 分钟稳定运行无持续线性增长 | 通过开发者工具性能面板观察 |
| 发布内容包体 | ≤ 4 MB（项目内部预算） | 以 `game.js`、`dist/`、`assets/` 合计计算 |
| `dist/` 编译产物 | ≤ 1 MB（项目内部预算） | 超出需说明依赖或拆包方案 |

## 2. 可重复基准

在项目目录执行：

```text
npm run bench:simulation
node --experimental-strip-types scripts/benchmark-simulation.mjs --strict
```

脚本默认使用 220 人、180 帧、30 帧预热，输出平均值、P50、P95、最大值、估算
FPS 和堆变化。可用参数做趋势对比：

```text
node --experimental-strip-types scripts/benchmark-simulation.mjs --actors=60 --frames=600
node --experimental-strip-types scripts/benchmark-simulation.mjs --actors=220 --frames=600 --warmup=60 --budget=33.3 --strict
```

2026-09-01 的一次 Node 基线（运行环境：Node 25，非目标手机）如下，仅作为回归
参考：

```text
actors: 220
p95Ms: 2.143
maxMs: 3.101
estimatedFpsAtP95: 466.6
```

如果硬件、Node 版本或帧数改变，应把完整 JSON 输出保存到性能记录，而不是只摘录
一个数字。`--strict` 只判断逻辑更新 P95，不宣称真机已经达标。

## 4. 当前实现与优化边界

- 规则层使用空间哈希和固定步长；M7 重点观察 200+ 角色下的邻域查询和碰撞分离。
- Canvas 采用单一整帧入口，SVG 资源保留为登记资产，当前角色优先用几何绘制，
  避免每帧图片解码和网络加载。
- 运行时只维护一条 scheduler/ticker；快速启停和切关由 M7 测试锁定。
- 若低端机不达标，优先按顺序处理：降低远处角色更新频率、减少重复路径绘制、
  复用临时对象、降低特效粒度；不得改变安全区、容量和结算规则来“优化”指标。

## 5. 性能退出条件

- 自动化 `--strict` 基准通过，且记录提交版本和运行环境。
- D-03（低端 Android）星环城整帧 P95 ≤ 33.3 ms，无连续 5 帧以上长帧。
- 10 分钟运行和 5 次切后台/重试后无持续内存增长或 ticker 倍增。
- 发布审计显示包体、音频和 SVG 均未超过内部预算。
