# M8-A 视觉重制说明

这是一套独立的“潮汐线”视觉样板，不以任何现实地铁运营方、站牌、制服或车辆外观为目标。它只借鉴俯视人群通行这一类抽象玩法，具体的车体比例、角色轮廓、配色、动效和文案均重新设计。

## 本轮目标

- 车厢从单色矩形升级为可读的空间结构：外壳、车顶压边、连续窗带、内饰暗部、座椅、地板透视线、门洞、门框、灯带和门槛。
- 站台从网格底图升级为有尺度的材质：错位地砖缝、排水槽、盲道点阵、金属边缘和潮汐导向线。
- 乘客从圆形标记升级为小型角色：头部、发型、上衣、裤脚、手臂、鞋、脚底投影和类型配件。
- 玩家使用独立的潮汐青外套、背包、帽檐、徽章和方向箭头，保证在拥挤场景中仍可识别。

## 运行时约束

1. 只使用项目已有的 Canvas 基础 API；不依赖渐变、图片解码、`clip` 或外部字体。
2. 所有几何细节都保留低版本 Canvas 回退路径，图片资源加载失败时游戏仍可玩。
3. 角色动画使用确定性的 ID 相位和局内时间，不改变规则层状态，也不引入新的随机源。
4. 角色按车内/站台以及 y 坐标排序绘制，玩家最后绘制，确保遮挡关系稳定。
5. 375×667 为最低可读性基准；414×896 用于检查留白、HUD 和触控区。

## 后续批量资产计划

本轮先以 Canvas 向量样板验证尺度和风格。样板关卡在真机上确认后，再按同一轮廓规范生成 PNG/SVG atlas：

1. 为玩家和六类乘客各制作 idle、行走、疏导、上车四个关键帧。
2. 为车厢制作开门、关门、阻塞三种状态图层，而不是用单一换色表示状态。
3. 在 `assets/ASSET_MANIFEST.md` 记录生成工具、版本、提示词/修改过程、文件哈希和最终许可。
4. 资源接入后保留当前几何回退，并在微信开发者工具和至少一台真机上做截图回归。

## 版权复核

独立配色和抽象空间结构不能替代相似性审查。发布前仍需检查：角色姿态是否形成可识别的原作轮廓、车厢窗门比例是否过度接近参考作品、UI 布局和动效节奏是否构成整体模仿，以及所有字体、音效和生成素材是否有可追溯许可。

## M8-A.1 反馈修正

- 上车触发区扩展到车门安全区内沿；门前乘客不再被站在安全区的玩家碰撞推回。
- 上车目标改为所选车门内侧的地板座位，并提高上车过渡速度；角色会明确穿过门槛后再就位。
- 车内地板、灯带、座椅和门洞使用更高明度配色；乘客使用更大的高对比轮廓和地板反光。
- 乘客不绘制持续行动方向线；站台长导向线改为静态装饰块，门前只保留状态圆点。

## M8-A.2 NPC 独立造型样板

- 普通、快步、慢行、行李、手机和同行组已分别使用独立的身体轮廓参数与姿态。
- 轮廓之外增加挎包、飘动围巾、帽杖、旅行箱、连帽衫/耳机和同行缎带等识别物件；
  颜色仅作为辅助，不再承担全部类型辨识。
- 造型集中登记在 `src/render/actor-renderer.ts` 的 `NPC_VISUAL_PROFILES`，继续沿用
  横屏紧凑缩放、确定性步频和疏导后的弹跳反馈。

## M8-A.3 车厢主题配色

- 三个 MVP 关卡共用同一套平面车厢几何结构，通过 `LevelConfig.carriageTheme` 切换外观。
- 前期海风门使用珍珠白，中期云港使用浅黄色，后期星环城使用青绿色；门的开闭、阻塞和安全区仍使用统一的状态语义色。
- 站台地板统一改为浅灰蓝，并在 `src/render/design-tokens.ts` 与 `assets/design-tokens.json` 中保持同步。

## M8-A.4 车厢纵向比例与开门时序

- 车厢规则尺寸统一为 `320 × 300`，底边继续与站台门线重合；横屏仍将车厢排在站台上方。
- 车门关闭或被事件阻塞时不绘制 `inside`、`boarding`、`alighting` 角色；只有门真正打开且未阻塞后，车内下车角色才沿门洞航点开始移动。
- 规则层与渲染层共用同一门状态，避免角色在画面隐藏时仍穿过不可用车门。
