# 《挤上这班车》开发落地计划

文档版本：0.1

目标：在不依赖浏览器 DOM/CSS、不引入现实地铁品牌和未授权资源的前提下，完成一个可在微信小游戏中运行的 3 关 MVP，再扩展到 12 站完整战役。

## 1. 执行原则

1. 先过权利与范围闸门，再写大批量代码。
2. 先做“移动—人流—疏导—进入—结算”的最小闭环，再扩内容和美术。
3. 规则层与微信 API 隔离；`src/core` 不得引用 `wx`、`document`、`window`、Canvas 或 CSS。
4. 每个阶段都有可运行产物和可验证验收标准，不以“代码写完”作为完成条件。
5. 所有外部资源进入工程前必须登记来源、许可证和商用范围。

## 2. 总体依赖顺序

```text
M0 权利/范围确认
  → M1 微信工程启动
  → M2 纯规则核心
  → M3 Canvas 渲染  ┐
  → M4 平台适配    ├→ M5 三关 MVP 集成
  → M6 资源与声音  ┘
  → M7 设备测试与性能
  → M8 审核、发布与监控
```

M3、M4、M6 在 M2 的接口稳定后可以并行；M7 之前不能冻结为“可发布版本”。

## 3. 里程碑总览

| 里程碑 | 目标 | 产物 | 通过标准 |
|---|---|---|---|
| M0 | 权利和范围清晰 | 权利清单、题材冻结单 | 无现实品牌依赖，资源规则明确 |
| M1 | 工程可启动 | 微信小游戏占位画面 | DevTools 可运行、无 DOM/外链请求 |
| M2 | 规则可测试 | `core` 模型与测试 | 规则在无渲染环境下可重复运行 |
| M3 | 画面可读 | Canvas 世界、角色、HUD | 关键状态无需网页 UI 也能理解 |
| M4 | 设备可操作 | 触摸、存储、音频、生命周期适配 | 真机完成移动、暂停、恢复、存档 |
| M5 | MVP 可玩 | 3 关完整闭环 | 新用户能完成首关并看到结算 |

## 4. 详细工作项与顺序

### M0：权利、题材和范围闸门

**依赖：无。建议先完成再进入正式开发。**

| 编号 | 工作项 | 交付物 | 验收 |
|---|---|---|---|
| R-01 | 确认这是独立重写，不复制参考项目代码、PRD 原文和素材 | 独立创作声明 | 新仓库中没有参考项目源码或资源 |
| R-02 | 冻结虚构城市、线路和站名，并做重名/商标初查 | 题材冻结表 | 不使用现实运营方名称、Logo 或官方地图 |
| R-03 | 建立资源来源模板 | `assets/ASSET_MANIFEST.md` 模板 | 每种资源都有来源、许可证、版本字段 |
| R-04 | 决定新工程许可证 | 许可证决策记录 | 明确作者、贡献者和商用权限后再添加 LICENSE |
| R-05 | 定义内容边界 | 内容审核清单 | 无血腥、伤害、危险交通行为和现实官方暗示 |

**M0 退出条件：** 产品名确定为《挤上这班车》，线路和站名均为虚构；所有团队成员知道“玩法可参考，表达必须独立”。

## 5. 可并行的工作流

在 M2 接口稳定后可以拆成四条线：

- **规则线：** 状态机、碰撞、容量、评分和测试。
- **表现线：** Canvas 渲染、UI、动效和布局。
- **平台线：** 触摸、存储、音频、生命周期和构建。
- **资源线：** 角色、字体、图标、音效和许可证清单。

每条线只通过明确的数据接口协作，不直接修改其他线的内部状态。

## 7. 测试矩阵

### 核心规则

- 玩家在车门关闭前进入安全区应成功，之后进入应失败。
- 下车流优先通过时，玩家逆向碰撞会降低礼让度。
- 车厢达到临界容量时仍可判定入口，但评分发生变化。
- 疏导只影响作用范围和方向正确的目标，并扣除体力。
- 相同随机种子重放得到相同事件和结果。
- 存档版本升级不会把已解锁关卡清零。

### 平台与设备

- 首次点击后音频播放；静音后不再播放。
- 摇杆按下、拖动、离开、取消和多指输入均能释放状态。
- 切后台 10 秒再回来，倒计时不会跳过 10 秒。
- 375×667、414×896、横向调试窗口均不遮挡关键按钮。
- 无网络时可启动、游玩和结算。

### 性能

- 记录逻辑更新、碰撞、排序、绘制各阶段耗时。
- 角色数量达到目标上限时观察帧率和内存。
- 避免每帧创建大量临时数组、字符串和 Canvas 路径；必要时引入对象池和邻域更新。

## 8. 风险登记

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 微信 Canvas API 差异 | `roundRect`、文本或 DPR 表现不一致 | 兼容辅助函数、最低基础库实测 |
| 低端机卡顿 | 帧时间超过 33ms | 限制角色数、邻域更新、对象池、减少路径绘制 |
| 生成资源相似第三方作品 | 角色/字体/音频出现可识别相似点 | 重生成、人工修改、保留复核记录 |
| 品牌联想过强 | 名称、配色或截图像现实运营方 | 虚构化、改视觉、加非官方声明 |
| 玩法范围膨胀 | MVP 还没闭环就增加 12 站、商城、排行 | 将非 MVP 需求放入 backlog |
| 生命周期状态错乱 | 重试后速度加倍或音效重复 | 单一 ticker、启动 token、前后台测试 |
| 存档损坏 | JSON 解析异常或版本字段缺失 | 版本化 schema、校验和安全回退 |
| 审核材料与实际内容不一致 | 截图仍出现旧名字/旧 Logo | 发布前逐页核对素材和文案 |

## 9. Definition of Done（MVP）

只有同时满足以下条件，MVP 才算完成：

- 三个关卡均能从启动进入、游玩、成功/失败、结算、重试和返回主页。
- 规则测试、真机触摸测试和前后台测试通过。
- 目标低端机至少 30 FPS，且没有明显输入延迟或状态卡死。
- 工程没有 DOM、CSS、外链字体、未登记图片或未登记音频依赖。
- 线路、站名、角色、字体、音效、图标和文案均为自有或有明确授权。
- 许可证、第三方声明、资源清单、隐私/适龄/非官方声明已准备好。
- 生产包使用正式配置，调试日志和测试 AppID 已移除。

## 10. 首轮实际执行清单

下一轮开发按以下顺序开始，不先扩展完整战役：
